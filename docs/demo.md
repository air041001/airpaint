# AirPaint 封版演示记录

## 目的与证据边界

这份记录用于长期保存和演示当前产品，不是新的图片质量测试。

- 页面来自仓库当前 `web/index.html`，按桌面 `1440×1000` 与移动端 `390×844` 实际渲染。
- 展示图片是本项目已有生成结果，不是他人作品；演示未再次调用 GPU、Reasoning Model 或 Vision Model。
- 历史卡片、配额和异常状态由本地演示夹具提供，因此只证明界面状态可见、可操作，不证明一次新的实时生成成功。
- 后端持久化、恢复和 ComfyUI 协议另由自动测试、真实启停 smoke 与在线备份/恢复验证覆盖。
- D59 的五张参考图/Img2Img 结果没有全部通过人眼验收，不能从本演示截图推导为画质完成。
- 两张单独保存的项目真实生成图及其 PNG 内嵌 workflow 参数见 [真实案例与已有参数](showcase.md)。

## 三分钟演示路径

1. 使用邀请码登录。首次登录后浏览器改用签名 HttpOnly cookie，不在本地长期保存邀请码。
2. 在“画面描述”输入中文构思，选择补全程度、尺寸、精修与 LoRA；可先看 Concept/Prompt，也可直接生成。
3. 生成结果旁检查可编辑的中文构思、英文 Prompt、真实 seed、尺寸与 LoRA 绑定。
4. 在“最近作品”中演示四类状态：已完成、图片待取回、状态待核对与失败。前两类恢复操作只查询或重新下载，不创建新任务。
5. 从一张历史图片进入“迭代暗房”，切换“换一版”或“基于此图重绘”；指出父版本、源图、seed 策略与整图重绘限制。
6. 刷新或重新登录，确认服务端历史重新出现；切换纸本/石墨主题，并在移动端查看 Prompt 与参数分页。

### 浏览器验收摘要

- 桌面纸本与石墨主题均能恢复最近结果、Prompt、seed、4/90 配额和异常状态卡片。
- 从历史作品进入暗房后，源图、父版本、尺寸、seed、换一版和整图重绘入口均可见。
- 移动端两种主题无横向溢出；Prompt、参数、历史和暗房按单列顺序可访问。
- 纸本主题下的“画幅适配”已从近黑色不可读下拉框修为浅色可读控件。
- 浏览器没有新增脚本错误；仍有 Tailwind CDN 的生产提示，作为已知外部依赖保留。

## 后端演示证据

- 使用临时本地 ComfyUI 协议替身启动真实 AirPaint 进程，`/api/health` 同时报告 Web、ComfyUI 与数据库可用。
- 邀请码登录返回 HttpOnly cookie；随后只带 cookie 即可读取 workflow 和空历史，日限额为 90。
- 停止脚本触发应用正常关闭流程，日志出现完整 shutdown，不需要强制终止。
- 对实际空库执行在线 SQLite 备份，校验 manifest、哈希、schema 和 integrity 后，恢复到隔离目录再次验证；没有覆盖生产目录。

## 演示时必须主动说明

- AirPaint 是 ComfyUI 上层的 Prompt/Intent/Knowledge 工具，不是 ComfyUI 替代品。
- Img2Img 是整图重新采样，不保证只改一处，也不保证人物、发型或构图完全保持。
- 参考图、多人构图和 LoRA 最终效果仍受模型与 seed 影响；结构测试不能替代人眼验图。
- 当前是单机、单 worker、SQLite 版本；它追求可恢复的个人使用，不是分布式生成平台。
