2026-09-09，在用户选定「沉浸展台」后完成最后一次前端收尾。页面继续使用现有生产请求逻辑，没有新增模型或工作流能力。

- 页面与操作使用隔离的本地 API 夹具。截图中的 seed、配额、任务身份和状态属于模拟数据，不能当作这张原图的真实生成参数。
- 两张另存的真实生成图及 PNG 内嵌 workflow 参数见 [真实案例](showcase.md)。D59 的未通过人眼结论保持不变。
- 浏览器检查由 Luna 完成；后半段仅做只读 UI QA，代码修改、确定性测试和交付由主 Agent 完成。

## 当前界面

![AirPaint 沉浸展台，1440×1000](assets/airpaint-workshop.png)

主图完整适应可用空间。编辑器默认收起，桌面展开宽 520px；构思、Prompt 和成像设置按页签查看，手机单独适配。图片可点击放大。

## 演示路径

1. 使用邀请码登录，浏览器随后通过签名 HttpOnly cookie 访问，不长期保存邀请码。
2. 点击底部构思栏，在「画面构思」填写中文、选择补全程度，按需添加参考图。
3. 在「成像设置」选择画幅、文生图/图生图、精修和 LoRA；角色 Profile 与强度沿用既有规则。
4. 点击「先看 Prompt」，检查或编辑中文构思、英文 Prompt，再确认生成；也可以直接生成画面。
5. 从「所有作品」切换横图和竖图，确认未提交草稿保持不变。作品参数属于选中的记录，不是下一次生成的设置。
6. 点击「继续创作」进入真实 session 的「本次迭代」。选择任意已有版本作为源图，换一版或整图重绘；父版本标注来自保存的关系。
7. 在「所有作品」检查失败原因和需要核对的任务。恢复只核对或取回原任务，不创建新的生成请求。

## 验证记录

## 后端证据与边界

后端沿用 `v1.0.0`（`9af5604`）的持久化、幂等、归属、真实启停和备份/恢复验证，本次没有重新运行 GPU 生成或改动这些协议。

AirPaint 是单机、单 worker、SQLite 的可恢复绘图应用。Img2Img 是整图重新采样，不保证只改一处或保住人物、发型、构图；参考图、多人和 LoRA 的效果仍受模型与 seed 影响。界面验收不能替代图片质量验收。
